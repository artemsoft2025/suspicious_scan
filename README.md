# suspicious_scan v1.8.3

Эвристический сканер подозрительных файлов, автозапуска,
реестра и процессов

## О ПРОГРАММЕ

**suspicious_scan** — эвристический сканер для Windows. Ищет подозрительные
файлы, записи автозапуска, закрепление в реестре и активность процессов.

ВАЖНО: сканер НИЧЕГО НЕ УДАЛЯЕТ. Он только читает информацию и выводит
отчёт. Все решения об удалении или лечении — за пользователем.

Программа не является антивирусом. Это вспомогательный инструмент для
поиска того, что стоит проверить вручную.

## ВАЖНО ПЕРЕД ЗАПУСКОМ

Во время работы сканера рекомендуется ВРЕМЕННО ОТКЛЮЧИТЬ АНТИВИРУС
(или добавить папку со сканером в его исключения).

Причины:

- сканер читает реестр, список процессов и вызывает PowerShell —
  антивирусы реагируют на такое поведение как на подозрительное;
- активный антивирус может блокировать PowerShell-скрипт внутри
  --procmon (в частности, Huorong ломает AmsiScanBuffer, из-за чего
  модуль процессов падает с ошибкой 3221225477);
- антивирус может частично удалить или заблокировать suspicious_scan.exe
  при первом запуске.

После сканирования антивирус включите обратно.
Сканер сам по себе безопасен: он ничего не пишет в систему,
не изменяет реестр и не отправляет данные в интернет.

## ОСНОВНЫЕ РЕЖИМЫ РАБОТЫ

1. Сканирование файлов
   
   ```
   suspicious_scan.exe C:\Users\user
   suspicious_scan.exe c:\ d:\ e:\
   ```
   
   Ищет подозрительные файлы в указанной папке или на дисках.
   Что проверяется:
- двойные расширения (фото.jpg.exe, video.avi.cmd)

- длинные пробелы перед расширением (фото        .exe)

- юникод-точки в имени (обход определения расширения)

- bidi/RTL-override в имени

- подмена похожими символами (svch0st.exe, micros0ft.exe)

- гомоглифы (латиница + кириллица в одном слове)

- очень длинное имя и много точек в имени

- скрытые и системные атрибуты у программных файлов

- цифровая подпись PE (встроенная и каталожная Windows)

- имя системного процесса с несистемным расширением (svchost.bat)

- autorun.* в корне диска (вектор USB-червя)

- PE внутри, но расширение не-PE (.vbs, .bat)

- файлы без подписи в подозрительных папках

- ярлыки .lnk (цель, аргументы, рабочая папка)

- зона скачивания Zone.Identifier (с флагом --zone)
2. Проверка автозапуска
   
   `suspicious_scan.exe --autostart`
   
   Что проверяется:
- HKCU\...\Run, RunOnce

- HKLM\...\Run, RunOnce (+ Wow6432Node)

- папки Startup (пользовательская и общая)

- задачи планировщика (C:\Windows\System32\Tasks\)
  
   Для полного скана планировщика нужны права администратора.
3. Проверка реестра (закрепление)
   
   `suspicious_scan.exe --registry`
   
   Что проверяется:
- AppInit_DLLs (DLL, загружаемые в каждый GUI-процесс)

- Image File Execution Options (перехват процессов через Debugger)

- Winlogon Shell / Userinit / Taskman
  
   Для полного скана нужны права администратора.
4. Проверка процессов
   
   `suspicious_scan.exe --procmon`
   
   Что проверяется:
- высокая загрузка CPU (от 20% на ядро и выше)

- процессы без окна с нагрузкой (майнеры)

- неподписанные PE

- системное имя вне системных папок (svchost.exe в TEMP)

- опасные аргументы (-enc, IEX, DownloadString)

- пути в %TEMP%, %APPDATA%, Downloads, Public

- соединения на порты майнеров (3333, 4444, 5555, ...)

- аргументы майнера (--algo, stratum+tcp://)
  
   Для полной информации о процессах нужны права администратора.
5. Всё вместе
   
   `suspicious_scan.exe C:\ --autostart --registry --procmon`
   
   Все четыре модуля в одном отчёте.

## ПОЛЕЗНЫЕ ПАРАМЕТРЫ

```
  --min-score N
      Минимальный скор для попадания в отчёт. По умолчанию 20.
      Больше значение — меньше находок, но меньше шума.
      Меньше значение — больше находок, включая слабые сигналы.
      Рекомендуется: 20-40 для реальных сканов, 1-10 для тестов.

  --top N
      Показать в консоли только N верхних находок.
      В JSON-отчёт попадут все.

  --json FILE
      Сохранить отчёт в JSON-файл. Удобно для анализа или
      для отправки разработчику.

  --zone
      Учитывать Zone.Identifier (метка «скачан из интернета»).
      Работает только на NTFS.

  --hash-cache FILE
      SQLite-кэш SHA-256. При повторных сканах хэши уже
      проверенных файлов берутся из кэша — ускоряет работу.

  --threads N
      Количество потоков для анализа. По умолчанию 8.
      Больше — быстрее на многоядерных машинах.

  --exclude PATH
      Исключить путь из сканирования. Можно указать несколько раз:
        --exclude C:\Backup --exclude D:\Games
      На текущей версии работает для файлового скана.

  --follow-symlinks
      Переходить по симлинкам при обходе. По умолчанию — нет.

  --log FILE
      Файл лога. По умолчанию suspicious_scan.log в текущей папке.

  --no-banner
      Не печатать баннер при запуске.

  --version
      Показать версию и выйти.

  --help
      Полная справка по параметрам.
```

## ПРИМЕРЫ ЗАПУСКА

```
Проверить конкретную папку:
    suspicious_scan.exe C:\Users\user\Downloads

Проверить весь диск C: с сохранением в JSON:
    suspicious_scan.exe C:\ --json report.json

Проверить всё, что можно, и сохранить отчёт:
    suspicious_scan.exe C:\ --autostart --registry --procmon --json full.json

Показать только 10 самых подозрительных файлов:
    suspicious_scan.exe C:\ --top 10

Проверить только процессы:
    suspicious_scan.exe --procmon

Проверить только автозапуск и реестр:
    suspicious_scan.exe --autostart --registry

Повторный скан с кэшем хэшей:
    suspicious_scan.exe C:\ --hash-cache hashes.db

Проверить, есть ли метка «скачан из интернета»:
    suspicious_scan.exe C:\Users\user\Downloads --zone

Проверить папку с переходом по симлинкам:
    suspicious_scan.exe D:\Data --follow-symlinks
```

## КАК ЧИТАТЬ ОТЧЁТ

```
Формат вывода:

    --- [СКОР] ПУТЬ_К_ФАЙЛУ
        размер: ...
        sha256: ...
        VirusTotal:    https://...
        Kaspersky TIP: https://...
        [СКОР] копия N: путь
            [причина 1]
            [причина 2]
```

СКОР — число от 0 до 100+. Чем выше, тем подозрительнее.
Ссылки на VirusTotal и Kaspersky OpenTIP — можно кликнуть и
посмотреть репутацию файла по хэшу. Файл при этом никуда
не загружается, только SHA-256.

Если у файла несколько копий с одинаковым содержимым (одинаковый
SHA-256), они группируются в одну запись — экономит место и
показывает, что файл расползся по нескольким местам.

## ПРАВА АДМИНИСТРАТОРА

Без прав администратора сканер работает, но видит меньше:

- не все задачи планировщика
- не все ключи реестра
- не все процессы (путь и командная строка)

Если в логе есть предупреждение про права — запустите сканер
от администратора для полного скана:

1. Win+X
2. «Терминал (Администратор)» или «Командная строка (Администратор)»
3. cd C:\путь\к\suspicious_scan
4. suspicious_scan.exe --autostart --registry --procmon

## ВОЗМОЖНЫЕ ПРОБЛЕМЫ

Антивирус ругается на suspicious_scan.exe или ломает --procmon

    Сканер читает реестр, список процессов и вызывает PowerShell —
    антивирусы реагируют на это как на подозрительное поведение.
    Отключите антивирус на время работы или добавьте папку
    в исключения. Известный случай: Huorong ломает AmsiScanBuffer
    в PowerShell, из-за чего --procmon падает с rc=3221225477.
    С отключённым антивирусом работает штатно.

Не находит то, что ожидалось

    Проверьте --min-score. По умолчанию 20. Понизьте до 10 или 1,
    чтобы увидеть слабые сигналы. Учтите: при --min-score 1
    появляется много шума из Recent, Public и т.п.

Пусто в JSON, но есть находки в консоли

    В JSON попадают только находки со скором >= --min-score.
    Понизьте порог.

Не видит задачи планировщика

    Запустите от администратора.

Ложное срабатывание на Chrome / Electron / crashpad_handler

    Правило «процесс без окна с загрузкой CPU >= 20%» может давать
    +20 на подписанные процессы (Chrome в фоне, crashpad_handler
    от WireSock/Electron и т.п.). Это ожидаемое поведение эвристики:
    смотрите на совокупность причин, а не на одну строку.
    В v1.8.4 планируется смягчить правило для подписанных PE
    в безопасных путях.

Битые ярлыки и задачи планировщика в логе (DEBUG)

    Иногда в логе встречаются строки вида:
        lnk.path error ... UwpSegmentEntry found
        pylnk3 не разобрал ... unpack requires a buffer of 2 bytes
        Не удалось разобрать задачу ... no element found
    Это НЕ ошибка сканера. Он корректно пропускает битые или
    UWP-ярлыки Windows 11 (WinX) и задачи планировщика с
    нечитаемым XML. Скан не прерывается, файл просто не
    анализируется.

Долго работает --procmon

    Модуль процессов использует PowerShell и WMI, в среднем
    15-40 секунд в зависимости от числа процессов и прав.
    Это нормально.

## БЕЗОПАСНОСТЬ

Сканер НЕ:

- не удаляет файлы
- не изменяет реестр
- не пишет в системные папки
- не отправляет данные в интернет

Сканер только ЧИТАЕТ информацию и выводит отчёт.

Ссылки на VirusTotal и Kaspersky OpenTIP открываются в браузере
по вашему решению. Если кликнуть — уйдёт только SHA-256 файла,
сам файл никуда не загружается.
